# Bash `exec` 命令核心用法总结

`exec` 是 Bash 的内置命令，其行为分为**两大模式**：**文件描述符操作模式**（无命令参数）和**进程替换模式**（带命令参数）。在日常脚本中，前者（操作 FD）是处理重定向的核心，后者（替换进程）常用于优化性能。

---

## 模式一：文件描述符操作（无命令参数）

**语法结构**：`exec [重定向规则]`

**核心作用**：**在当前 Shell 进程内部**（不创建子进程）直接修改文件描述符（FD）的指向。修改会持续影响后续所有命令，直到被显式恢复或脚本结束。

### 1. 复制/备份文件描述符（读入方向）

| 语法 | 作用 | 底层模型（类比指针复制） |
|:-----|:-----|:----------------------|
| `exec N<&M` | 将 **FD N** 指向 **FD M** 当前指向的底层资源 | `[N] -> (指向 M 所指向的内核对象)` |

**示例可视化**（`exec 3<&0`）：
```text
执行前：                   执行后：
[0] -> 键盘（终端）        [0] -> 键盘（终端）
[3] -> (空)               [3] -> 键盘（终端）  # 复制了指针
```

### 2. 复制/备份文件描述符（写出方向）

| 语法 | 作用 | 底层模型 |
|:-----|:-----|:--------|
| `exec N>&M` | 将 FD N 指向 FD M 当前指向的底层资源（通常用于备份 stdout/stderr） | `[N] -> (指向 M 所指向的内核对象)` |

**示例可视化**（`exec 4>&1`）：
```text
执行前：                   执行后：
[1] -> 屏幕               [1] -> 屏幕
[4] -> (空)               [4] -> 屏幕  # 备份了标准输出
```

### 3. 打开文件作为新的文件描述符

| 语法 | 作用 | 说明 |
|:-----|:-----|:-----|
| `exec N< file` | 以只读方式打开文件，并分配给 FD N | 文件指针停留在开头 |
| `exec N> file` | 以写入方式打开文件（覆盖），分配给 FD N | 若文件不存在则创建 |
| `exec N>> file` | 以追加方式打开文件，分配给 FD N | 写入的数据从文件末尾开始 |
| `exec N<> file` | 以读写方式打开文件，分配给 FD N | 常用于操作块设备或特殊文件 |

**示例可视化**（`exec 5< data.txt`）：
```text
执行前：                   执行后：
[5] -> (空)               [5] -> data.txt（内核文件对象）
```

### 4. 移动文件描述符（交换指针）

| 语法 | 作用 |
|:-----|:-----|
| `exec N<&M-` | 将 FD M 复制给 FD N，然后关闭 FD M（相当于"剪切"操作） |
| `exec N>&M-` | 同上，用于输出方向 |

### 5. 关闭文件描述符

| 语法 | 作用 | 底层模型 |
|:-----|:-----|:--------|
| `exec N<&-` | 关闭 FD N（输入方向） | `[N] -> (NULL)`，内核引用计数减 1 |
| `exec N>&-` | 关闭 FD N（输出方向） | `[N] -> (NULL)`，内核引用计数减 1 |

**示例可视化**（`exec 3<&-`）：
```text
执行前：                   执行后：
[0] -> 键盘               [0] -> 键盘
[3] -> 键盘               [3] -> (空)  # 引用计数减少，但键盘依然存在
```

## 模式二：进程替换（带命令参数）

**语法结构**：`exec [命令] [参数...]`

**核心作用**：用指定的新程序替换当前 Shell 进程。进程 PID 保持不变，但当前 Shell 的代码段、数据段、堆栈被完全覆盖。执行成功后，当前脚本立即终止（不执行后续任何代码）。

### 典型应用场景

| 典型场景 | 示例 |
|:---------|:-----|
| 在脚本末尾将控制权永久移交给另一个程序 | `exec java -jar app.jar` |
| 将当前 Shell 替换为解释器（常用于 #!/bin/sh 的优化） | `exec /usr/bin/python3 "$@"` |
| 永久重定向脚本的所有后续输出（不替换进程） | `exec > log.txt 2>&1` |

**注意**：若 exec 后跟命令且执行失败，当前 Shell 会继续运行后续代码；若执行成功，后续代码永不执行。

## 综合实战可视化模型（完整生命周期）

假设我们要在读取文件的同时，保留键盘输入能力：

```bash
# 步骤 1：备份键盘（FD 0）到 FD 3
exec 3<&0
# 状态：[0]->键盘, [3]->键盘

# 步骤 2：将标准输入重定向到文件
exec 4< data.txt
# 状态：[0]->键盘, [3]->键盘, [4]->data.txt

# 步骤 3：在 while 中从 FD 4 读取，同时用 FD 3 交互
while read -r line <&4; do
    read -p "确认?" <&3  # 读取键盘
done

# 步骤 4：清理资源（关闭所有自定义 FD）
exec 4<&-   # 关闭 data.txt
exec 3<&-   # 关闭键盘备份
# 状态：[0]->键盘, [3]->空, [4]->空
```

## 核心操作符速查表

| 操作符 | 含义 | 适用方向 |
|:-------|:-----|:---------|
| `N<&M` | 复制输入源（M 复制给 N） | 输入（stdin） |
| `N>&M` | 复制输出目标（M 复制给 N） | 输出（stdout/stderr） |
| `N<&-` | 关闭输入描述符 N | 输入 |
| `N>&-` | 关闭输出描述符 N | 输出 |
| `N< file` | 只读打开文件赋给 N | 输入 |
| `N> file` | 只写覆盖打开文件赋给 N | 输出 |
| `N>> file` | 只写追加打开文件赋给 N | 输出 |

## 关键注意事项

### 1. 默认 FD 保留
`exec` 对 FD 的修改是永久性的，除非显式关闭或恢复，否则影响整个脚本生命周期。

### 2. 子进程继承
通过 `exec` 修改的 FD 默认会被后续子进程继承（除非设置了 close-on-exec 标志）。

### 3. 与管道的冲突
在管道（`|`）右侧使用 `exec` 修改 FD 时，修改仅作用于管道产生的子 Shell，主 Shell 不受影响。

### 4. 自动分配 FD
现代 Bash 支持 `exec {var}<> file` 语法，由系统自动分配空闲 FD 并存入变量 `var`，避免手动管理数字冲突。
