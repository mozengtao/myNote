# Layer 8 — 整合生产级真实 PCI 驱动与严密状态机

## 1. Mental Model

现在，我们把前面 7 个 Layer 散落的知识珠子，用一根金线串起来。
一个工业级 PCIe 设备驱动的生命周期绝不是几句简单的 API 罗列，而是一个高度防错、资源严格配对、具备容灾自愈能力的**有限状态机（Finite State Machine）**：

```
                      +-------------------+
                      |       RESET       |
                      +-------------------+
                                |
                                | probe() 进入
                                v
                      +-------------------+
                      |      PROBED       |
                      +-------------------+
                                |
                                | pci_enable_device + pci_request_regions + pci_iomap
                                v
                      +-------------------+
                      |  RESOURCES_READY  |
                      +-------------------+
                                |
                                | dma_alloc_coherent + pci_alloc_irq_vectors + request_irq
                                v
                      +-------------------+
                      |       READY       |
                      +-------------------+
                                |
                                | 硬件初始化完成，打开设备中断与 DMA 通道
                                v
                      +-------------------+
                      |      RUNNING      | <================+
                      +-------------------+                  |
                       /                 \                   |
      发生硬件超时/传输错误 /                   \ 收到卸载信号/热拔 |
                     v                     v                 |
          +-------------------+   +-------------------+      |
          |       ERROR       |   |     STOPPING      |      |
          +-------------------+   +-------------------+      |
                    |                       |                |
                    | 执行复位自愈           | 停止硬件 DMA   |
                    v                       v                |
          +-------------------+   +-------------------+      |
          |     RECOVERY      |   |      STOPPED      |      |
          +-------------------+   +-------------------+      |
                    |                       |                |
                    +-----------------------)----------------+
                                            | 释放 IRQ/DMA/MMIO 资源
                                            v
                                  +-------------------+
                                  |       RESET       |
                                  +-------------------+
```

## 2. 状态机全要素矩阵

在驱动的任意状态下，必须精确清点系统资源状态，并在 `remove()` 或错误处理中做出正确的释放动作：

| 状态 | 硬件使能? | BAR 映射? | DMA Buffer? | IRQ 注册? | 设备工作? | remove() 应该做什么？ |
|---|---|---|---|---|---|---|
| **RESET** | 否 | 否 | 否 | 否 | 否 | 无需释放任何资源 |
| **PROBED** | 否 | 否 | 否 | 否 | 否 | 仅释放驱动私有上下文结构体 |
| **RESOURCES_READY**| 是 | 是 | 否 | 否 | 否 | `pci_iounmap` + `pci_release_regions` + `pci_disable_device` |
| **READY** | 是 | 是 | 是 | 是 | 否 | 额外执行 `free_irq` + `dma_free_coherent` |
| **RUNNING** | 是 | 是 | 是 | 是 | 是 | 先发命令停止硬件，等待飞行的 DMA 结束，再走逆序注销 |
| **ERROR** | 是 | 是 | 是 | 是 | 异常 | 屏蔽中断，进入 RECOVERY 或直接回退到 STOPPING |
| **STOPPING** | 是 | 是 | 是 | 是 | 停止中 | 挂起新的请求，Drain（排空）排队中的数据 |
| **STOPPED** | 是 | 是 | 待释 | 待释 | 否 | 安全、确定性地逆序注销全部资源 |

## Checkpoint

- 为什么工业级驱动必须维护内部状态机变量（`enum dev_state`）？
- 当驱动处于 `RUNNING` 状态突然收到 `remove()` 信号时，为什么不能立即调用 `dma_free_coherent()`？
- 驱动中的错误跳转（`goto err_xxx`）与驱动卸载函数（`remove`）之间有什么深刻的对称性关系？
