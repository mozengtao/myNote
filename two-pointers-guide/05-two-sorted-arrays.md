# 双序列扫描（Merge Scan）

双序列扫描不是「两个数组各放一个下标」的写法。

它是：在 `A` 的下标 × `B` 的下标 这个矩形网格里，
利用**两边都递增**，每次把「当前更小的那一侧」整行或整列宣判死亡。

---

# 第一部分：它解决什么问题

适用于：

- 两个（或更多）已经有序的序列
- 要做归并、求交、求差、对齐、合并重叠区间
- 每个元素只需要和「对面当前最小还没消耗的元素」比一次

共同特点：

- 状态是 `(i, j)`：A 的进度，B 的进度
- A、B 都单调，所以当前最小值只可能是 `A[i]` 或 `B[j]`
- 更小的那一个，对面后面更大的值再也不可能比它更该先处理

为什么暴力一般是 O(n^2)：

对 A 的每个元素，扫完整段 B。
网格是 n × m 个格子。

真正需要搜索的是：

> 哪些 `(i, j)` 是「两边前缀都已正确消耗」的前沿。
> 不是任意配对。

---

# 第二部分：二维搜索空间

```
              j (B) -->
         0    1    2    3
      +----+----+----+----+
   0  |  * |  * |  * |  * |
      +----+----+----+----+
   1  |  * |  * |  * |  * |
i (A) +----+----+----+----+
   2  |  * |  * |  * |  * |
      +----+----+----+----+
   3  |  * |  * |  * |  * |
      +----+----+----+----+

暴力: 每个 * 比较 A[i] 与 B[j]
```

暴力为什么要遍历整个空间：

若无序，A[i] 可能和 B 里任何一个相等/更该合并，必须全看。

真正哪些区域不用搜索：

有序后，算法只走一条从 `(0,0)` 到 `(n,m)` 的单调路径：
每次 `i++` 或 `j++`（或都加）。

```
路径例子 (归并):

    (0,0) -> (1,0) -> (1,1) -> (2,1) -> (2,2) -> (3,2) -> (3,3)

路径左下方: 已经输出/已经比较完
路径右上方: 还没到，但会被未来的前沿切到
路径以外的大多数格子从未比较
```

```
      B
    +------------
  A | * . . .     * = 走过
    | * * . .     . = 永久不看
    |   * * .
    |     * *
```

---

# 第三部分：单调性

真正单调的是：

```
A[0] <= A[1] <= ... <= A[n-1]
B[0] <= B[1] <= ... <= B[m-1]

因此在 (i, j):
    A[i] 是 A 剩余部分的最小
    B[j] 是 B 剩余部分的最小
    全局剩余最小 = min(A[i], B[j])
```

图：

```
A: 1  4  7
B: 2  3  8

当前 (0,0): min=1=A[0]
A[0] 比 B 里所有还没看的都小? 不一定比后面小。
但 A[0] < B[0] <= B[1] <= B[2]
所以 A[0] 比 B 的全部剩余都小。

A[0] 可以立刻输出/结算
整行「i=0 配所有 j>=0 还去比较谁更小」不再需要
因为胜负已定: A[0] 最小
```

```
若 A[i] < B[j]:
    A[i] 对所有 B[j'] (j' >= j) 都更小
    整段「这个 A[i] 再和后面的 B 比大小」死亡
    必须 i++

若 A[i] > B[j]:
    对称，j++

若相等:
    交集合题: 收获一个交，两边都可以进
    归并题: 任选一侧输出（稳定排序通常先左）
```

哪些状态可以直接排除：

- 已消耗的前缀 A[0..i) 与任意未来 B 的组合：已经处理完
- 当前较小元素与对面整个后缀的「谁更小」比较：已由对面当前头代表

为什么：对面后缀只会更大。当前头已经是对面能拿出的最小反抗。

---

# 第四部分：指针移动规则

```
谁小，谁前进。
相等则按题意两边都前进，或先走规定的一侧。
```

为什么只能这样移动：

当前较小值已经是全局剩余最小。
把它留下、去动较大的一侧：较大侧变得更大，较小值仍然最小，你什么也没结算，还可能乱序输出。

如果反方向移动会发生什么：

```
i-- 或 j--:
    把已经输出/已经判定过的元素重新放回
    破坏「前缀已完成」不变量
    归并会重复，交集会重复计数

看见 A[i] < B[j] 却 j++:
    跳过的 B[j] 可能比后面的 A 都小
    归并乱序，差集会把不该删的删掉，交集可能漏
```

为什么不会漏掉答案：

每个元素恰好在它成为「当前剩余最小」的那一刻被处理。
有序保证这个时刻唯一且正确。
交集：相等才会收获，较小侧不可能再和对方更小的（已消耗）相等且没被看过——对方更小的已经扫过。

为什么以后永远不用回来：

```
不变量:
    A[0..i) 与 B[0..j) 之间的所有归并/交/差关系已经结算完毕
    未来只比较两个后缀
    前缀不会因为后缀出现新值而需要重开
```

有序不会在扫描中反转，所以前缀冻结。

# 第五部分：复杂度为什么下降

```
i 从 0 到 n，只增，最多 n 次
j 从 0 到 m，只增，最多 m 次
每轮至少推进一侧
循环次数 <= n + m
每轮 O(1) 比较
时间 O(n+m)
```

从二维空间看：

```
暴力 n*m 次比较

现在路径是一条从左上到右下的单调链
链长 <= n+m
链的每一步砍掉当前元素对面后缀的整段比较

n*m 个格子里只有 O(n+m) 个被访问
```

```
总移动次数 <= n + m <= 2 * max(n,m)
不会超过「两个指针各走一遍」
```

---

# 第六部分：统一心智模型

双序列扫描真正利用的是：

> **两个递增序列的当前头，足以代表各自整个后缀的最小值。**

为什么成立：

```
min(后缀A) = A[i]
min(后缀B) = B[j]
下一步必须消耗 min(A[i], B[j])
消耗之后该侧头前进
被消耗的元素对任意未来对面值都已经完成使命
所以指针不回头
```

两个指针都不会回头，因为回头等于否认「这个元素已经是当时的全局最小并已处理」。

## 例子 1：合并两个有序数组（LeetCode 88）

### 1）题目

`nums1` 长度为 m+n，前 m 个有序，`nums2` 长度为 n 有序。原地把 `nums2` 合并进 `nums1`。

示例：`nums1 = [1,4,7,0,0,0], m=3`, `nums2 = [2,3,8]` -> `[1,2,3,4,7,8]`

### 2）为什么想到双指针

暴力：拼接再排序 O((m+n) log(m+n))，或对每个 nums2 插入 nums1，O(n(m+n))。

两边有序。真正搜的是「下一个该写入的值来自哪一侧」。
从前往后写会覆盖 nums1 尚未读的值，所以从**尾部**写：
比较两个读指针的较大者写入写指针。较大者对另一侧后缀仍然更大。

单调性：从大到小归并，当前最大 = max(A[i], B[j])。

### 3）画出搜索过程

从后往前（避免覆盖）：

```
nums1: 1 4 7 _ _ _
nums2: 2 3 8
       i=2 j=2 write=5

7 vs 8 -> 写 8
nums1: 1 4 7 _ _ 8
             j=1 write=4
```

```
7 vs 3 -> 写 7
nums1: 1 4 _ _ 7 8
       i=1
```

```
4 vs 3 -> 写 4
nums1: 1 _ _ 4 7 8
```

```
1 vs 3 -> 写 3
然后写 2，再写 1
```

```
读A     读B          写
1 4 7 | 2 3 8 | _ _ _
每次取较大的放到写位置，该侧读指针--
```

### 4）为什么移动这个指针

当前较大的必须立刻占住末尾空位。
若移动较小侧：较大值还在，末尾会被更小的占住，结果乱序。

从前往后写（若另开数组）则取较小者前进，原理对称。

不会漏：每个元素在它成为当前最大（或最小）时写入一次。

### 5）状态剪枝

写 8 时 `j--` 剪掉：

```
(8 与 nums1 里所有 <=7 的剩余元素再比谁该最后)
已确定 8 最大，整列「B 的末尾」死亡
```

```
    B:2 3 8
A 1 | . . X
  4 | . . X
  7 | . . X     X = 8 已结算，不必再比
```

### 6）最终代码

Python:

```python
def merge_sorted_arrays(nums1, m, nums2, n):
    write = m + n - 1
    i = m - 1
    j = n - 1

    while i >= 0 and j >= 0:
        if nums1[i] > nums2[j]:
            nums1[write] = nums1[i]
            i -= 1
        else:
            nums1[write] = nums2[j]
            j -= 1
        write -= 1

    while j >= 0:
        nums1[write] = nums2[j]
        j -= 1
        write -= 1
```

C++:

```cpp
#include <vector>

void mergeSortedArrays(std::vector<int>& nums1, int m,
                       const std::vector<int>& nums2, int n)
{
    int write = m + n - 1;
    int i = m - 1;
    int j = n - 1;

    while (i >= 0 && j >= 0) {
        if (nums1[i] > nums2[j])
            nums1[write--] = nums1[i--];
        else
            nums1[write--] = nums2[j--];
    }
    while (j >= 0)
        nums1[write--] = nums2[j--];
}
```

### 7）复杂度分析

每个元素被读一次、写一次。`i` 与 `j` 只减。总移动 <= 2(m+n)。时间 O(m+n)，空间 O(1)。

### 8）这一题真正训练了什么

> 归并是矩形网格上的一条不回头路径。
> 从哪一头走，取决于覆盖约束；单调性都是「当前极值代表整个后缀」。

## 例子 2：两数组交集（LeetCode 349 / 350）

### 1）题目

350：求交集，重复次数取两边最小值。先排序再双指针讲原理（也可用哈希）。

示例：`A = [1,2,2,3]`, `B = [2,2,2,4]` -> `[2,2]`

### 2）为什么想到双指针

暴力：对 A 每个元素扫 B，O(nm)。

排序后两边递增。相等才是交；谁小谁不可能再和对方更小的头相交（对方更小的已扫过），该侧前进。

### 3）画出搜索过程

```
A: 1 2 2 3
B: 2 2 2 4

i=0 j=0  1<2  i++   1 比 B 全部剩余小，1 不在交
```

```
A: 1 2 2 3
B: 2 2 2 4
   i j     2==2  收获 2，i++ j++
```

```
     i j   2==2  收获 2，i++ j++
```

```
       i   j     3<4  i++
A 耗尽 停止
结果 [2,2]
```

### 4）为什么移动这个指针

`A[i] < B[j]` 必须 `i++`。
若 `j++`：丢掉的 B[j] 可能等于后面的 A，漏交；同时小的 A[i] 仍不在 B 里（因为 B 后面更大）。

相等必须两边都走：这个出现次数已经被配对消耗。

不会漏：每个可配对的相等值会在两头第一次对齐时被收下。
多出来的重复留在较大次数的一侧，最终被谁小谁走消耗掉。

### 5）状态剪枝

第一步 `i++` 丢掉 1：

```
(A 的 1, B 的 2/2/2/4)
1 小于对面当前头，因而小于对面整个后缀
整行「值 1」死亡
```

```
      2 2 2 4
   1  X X X X
   2  * . . .
```

### 6）最终代码

Python:

```python
def intersect_sorted(a, b):
    a = sorted(a)
    b = sorted(b)
    i = 0
    j = 0
    result = []

    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            result.append(a[i])
            i += 1
            j += 1
        elif a[i] < b[j]:
            i += 1
        else:
            j += 1

    return result
```

C++:

```cpp
#include <vector>
#include <algorithm>

std::vector<int> intersectSorted(std::vector<int> a, std::vector<int> b)
{
    std::sort(a.begin(), a.end());
    std::sort(b.begin(), b.end());
    int i = 0;
    int j = 0;
    std::vector<int> result;

    while (i < static_cast<int>(a.size()) && j < static_cast<int>(b.size())) {
        if (a[i] == b[j]) {
            result.push_back(a[i]);
            ++i;
            ++j;
        } else if (a[i] < b[j]) {
            ++i;
        } else {
            ++j;
        }
    }
    return result;
}
```

### 7）复杂度分析

排序 O(n log n + m log m)，扫描 O(n+m)。
扫描阶段两指针各走一遍，移动 <= n+m。
若输入已有序，只需 O(n+m)。

### 8）这一题真正训练了什么

> 交集是归并路径上「高度相等」的那些台阶。
> 较小的一侧整行与对面后缀不可能再相等。

## 例子 3：两数组差集

### 1）题目

经典：求在 A 中但不在 B 中的元素（可保留或不保留重复，这里保留 A 的相对出现：A 比 B 多出来的）。

示例：`A = [1,2,2,3]`, `B = [2,4]` -> `[1,2,3]`
（一个 2 被 B 抵消，另一个 2 留下）

### 2）为什么想到双指针

暴力：对 A 每个元素扫 B 或对每个做哈希删除。

有序后与交集同一条路径，只是收获条件改成 `A[i] < B[j]`（或 B 耗尽）。
`A[i] == B[j]` 表示这个 A 被抵消，两边前进。
`A[i] > B[j]` 表示这个 B 与当前 A 无关，B 前进（B 里更小的不可能再出现在后面的 A 差集判定里当匹配——后面 A 更大）。

### 3）画出搜索过程

```
A: 1 2 2 3
B: 2 4

1<2  1 不在 B  收获 1  i++
```

```
2==2 抵消  i++ j++
```

```
A 还剩 2 3
B 还剩 4
2<4  收获 2  i++
```

```
3<4  收获 3  i++
A 尽
结果 1,2,3
```

### 4）为什么移动这个指针

`A[i] < B[j]`：B 当前及后缀都 >= B[j] > A[i]，A[i] 不在 B，必须收获并 `i++`。
若这时 `j++`：可能跳过真正等于 A[i] 的 B，把不该留下的 A 留下，或反过来搞乱抵消。

`A[i] > B[j]`：这个 B 太小，匹配不了当前和未来？未来 A 更大，更匹配不了这个更小的 B。B 对差集已无用，`j++`。

### 5）状态剪枝

收获 1 时：

```
(1, B 的整个后缀) 全部「1 是否在 B」已决: 不在
整行死亡
```

抵消 2 时：

```
这一对 (2_A, 2_B) 从两边各删一个
重复计数减一
```

### 6）最终代码

Python:

```python
def difference_sorted(a, b):
    a = sorted(a)
    b = sorted(b)
    i = 0
    j = 0
    result = []

    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            i += 1
            j += 1
        elif a[i] < b[j]:
            result.append(a[i])
            i += 1
        else:
            j += 1

    while i < len(a):
        result.append(a[i])
        i += 1

    return result
```

C++:

```cpp
#include <vector>
#include <algorithm>

std::vector<int> differenceSorted(std::vector<int> a, std::vector<int> b)
{
    std::sort(a.begin(), a.end());
    std::sort(b.begin(), b.end());
    int i = 0;
    int j = 0;
    std::vector<int> result;

    while (i < static_cast<int>(a.size()) && j < static_cast<int>(b.size())) {
        if (a[i] == b[j]) {
            ++i;
            ++j;
        } else if (a[i] < b[j]) {
            result.push_back(a[i++]);
        } else {
            ++j;
        }
    }
    while (i < static_cast<int>(a.size()))
        result.push_back(a[i++]);
    return result;
}
```

### 7）复杂度分析

与交集相同：排序加一次合并扫描。扫描移动 <= n+m，时间 O(n+m)（不计排序）。

### 8）这一题真正训练了什么

> 交、差、并是同一条归并路径上的三种收获谓词。
> 指针移动规则不变，变的是「这一步谁被宣判」。

## 例子 4：Merge Sort 的 merge

### 1）题目

归并排序的合并步：把两个有序子数组合成一个有序数组。
这是双序列扫描的原型。

示例：`left = [1,4,7]`, `right = [2,3,8]` -> `[1,2,3,4,7,8]`

### 2）为什么想到双指针

若对每个位置在两个子数组里线性找最小，每次找最小是 O(n)，共 O(n^2)。

有序后当前最小必在两个头之一。每次 O(1) 决策。

### 3）画出搜索过程

```
L: 1 4 7
R: 2 3 8
out:

1<2  出 1
```

```
L:   4 7
R: 2 3 8
out: 1

2<4  出 2
```

```
3<4  出 3
4<8  出 4
7<8  出 7
出 8
```

```
i
1 4 7
j
2 3 8

每步 min 头前进
```

### 4）为什么移动这个指针

出 1 后必须 `i++`。若 `j++` 丢掉 2，2 会排到更后面甚至丢失，破坏有序。

一侧耗尽，另一侧整段拷贝：因为剩余段已经有序且全部 >= 已输出。

### 5）状态剪枝

出 1：

```
(1, 2)(1,3)(1,8) 不必再比
1 已是全局最小
```

```
整个第 0 行死亡，i 走到 1
```

### 6）最终代码

Python:

```python
def merge_two_runs(left, right):
    i = 0
    j = 0
    merged = []

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1

    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged
```

C++:

```cpp
#include <vector>

std::vector<int> mergeTwoRuns(const std::vector<int>& left,
                              const std::vector<int>& right)
{
    int i = 0;
    int j = 0;
    std::vector<int> merged;
    merged.reserve(left.size() + right.size());

    while (i < static_cast<int>(left.size()) &&
           j < static_cast<int>(right.size())) {
        if (left[i] <= right[j])
            merged.push_back(left[i++]);
        else
            merged.push_back(right[j++]);
    }
    while (i < static_cast<int>(left.size()))
        merged.push_back(left[i++]);
    while (j < static_cast<int>(right.size()))
        merged.push_back(right[j++]);
    return merged;
}
```

### 7）复杂度分析

每个元素恰好被搬一次。时间 O(n+m)，空间 O(n+m)（输出）。
归并排序整体因此是 T(n)=2T(n/2)+O(n)=O(n log n)。
**O(n log n) 里的线性项，就是这一次不回头的双序列扫描。**

### 8）这一题真正训练了什么

> 排序为什么能分治：因为有序子段的合并不必回看已输出前缀。
> Merge 是双指针把 O(n^2) 选择排序式合并打成 O(n) 的地方。

## 例子 5：合并区间（LeetCode 56）

### 1）题目

若干闭区间，合并所有重叠的，返回不相交区间列表。

示例：`[[1,3],[2,6],[8,10],[15,18]]` -> `[[1,6],[8,10],[15,18]]`

### 2）为什么想到双指针

暴力：每个区间和其它比是否重叠，O(n^2)，还要处理传递重叠（1-3 与 3-5 与 5-8）。

先按起点排序。排序后：

```
当前已合并段的 end 是一条扫描线
下一个区间要么:
    start <= end  -> 被当前段吞并，end = max(end, new_end)
    start > end   -> 当前段冻结，新开一段
```

这是「已完成前缀」对「下一个区间」的扫描。
第二个指针可以看成「当前活跃区间」，第一个是扫描位置。
单调性：起点递增，一个被冻结的段再也不可能和更后面的段因「中间空隙」而重新粘上——后面起点更大，空隙只可能更大。

严格说它是单序列上的「写指针 + 读指针」，但决策依赖**排序后的双端点扫描**，归入本类：
有序键让扫描不回头。

### 4）为什么移动这个指针

重叠则扩展 `end`，不新开段：中间没有空隙，后面若再重叠会继续扩。

不重叠必须冻结：起点已超过 end，后面起点更大，回过头再和旧段比一定仍不重叠。

若回头把旧段解冻：违背起点单调，会把已经分开的段错误再粘，或死循环。

### 5）状态剪枝

冻结 [1,6] 时：

```
([1,6], 所有 start>=8 的区间)
全部不重叠
整块「已关闭区间 × 未来区间」死亡
```

```
不必再做 O(n^2) 两两检测
每个区间只和「当前活跃段」比一次
```

### 6）最终代码

Python:

```python
def merge_intervals(intervals):
    if not intervals:
        return []

    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]

    for start, end in intervals[1:]:
        last_end = merged[-1][1]
        if start <= last_end:
            merged[-1][1] = max(last_end, end)
        else:
            merged.append([start, end])

    return merged
```

C++:

```cpp
#include <vector>
#include <algorithm>

std::vector<std::vector<int>> mergeIntervals(std::vector<std::vector<int>> intervals)
{
    if (intervals.empty())
        return {};

    std::sort(intervals.begin(), intervals.end(),
              [](const std::vector<int>& a, const std::vector<int>& b) {
                  return a[0] < b[0];
              });

    std::vector<std::vector<int>> merged;
    merged.push_back(intervals[0]);

    for (size_t i = 1; i < intervals.size(); ++i) {
        int start = intervals[i][0];
        int end = intervals[i][1];
        if (start <= merged.back()[1])
            merged.back()[1] = std::max(merged.back()[1], end);
        else
            merged.push_back({start, end});
    }
    return merged;
}
```

### 7）复杂度分析

排序 O(n log n)。随后每个区间读一次，write 段只增不减（或只扩展 end）。
扫描移动 n 次。总时间 O(n log n)，线性部分是双指针/扫描。

### 8）这一题真正训练了什么

> 先排序，把二维「任意两段是否相交」变成一维扫描。
> 活跃段是写指针，新区间是读指针。冻结 = 不回头。

# 双序列扫描总结

为什么两个指针都不会回头：

> 因为每一步消耗的是当时全局剩余的极值。
> 极值一旦消耗，它对整个对面后缀的关系已经定死。
> 回头等于把已经定死的前缀重新打开，而有序性并不提供新信息。

```
两边有序
    |
    v
两个头代表两个后缀的 min/max
    |
    v
消耗极值，该侧前进
    |
    v
路径长度 n+m
    |
    v
矩形网格被一条单调链切开
```

什么情况下应该想到这一类：

1. 两个序列，或一个序列里两段 run
2. 已经有序，或可以先排序且排序可接受
3. 问题是并 / 交 / 差 / 归并 / 按端点扫描
4. 当前比较能代表「这个元素 vs 对面整个后缀」
