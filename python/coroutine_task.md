# Python asyncio：协程（Coroutine）与任务（Task）深度对比

## 1. 核心定义（一句话概括）
- **协程（Coroutine）**：是“函数蓝图”（定义做什么）。
- **任务（Task）**：是“工作进程”（负责实际运行它）。

---

## 2. 从三个维度拆解

### 2.1 协程（Coroutine）—— 冰冷的“蓝图/生成器”
- **定义**：通过 `async def` 定义的函数，调用时返回的是一个协程对象。
- **本质**：底层是一个**生成器（Generator）**。它只是一堆指令的集合，记录了“我要去读数据库”、“我要去请求API”等步骤。
- **状态**：刚创建时处于**“闲置（Idle）”**状态。不占用 CPU，也不占用事件循环的调度资源。
- **关键误区**：只写 `my_coro = my_async_func()`，协程**什么都不会做**（就像一张写满菜谱的纸，放在那里是凉的）。
- **如何变“热”（执行）**：
  - 方式一：直接 `await coro`（挂在当前任务下执行）。
  - 方式二：用它创建 `Task`（交给事件循环独立调度）。

### 2.2 任务（Task）—— 运行中的“工人/未来”
- **定义**：通过 `asyncio.create_task(coro)` 或 `loop.create_task(coro)` 创建，返回一个 `Task` 对象。
- **本质**：`Task` 是 `Future` 的子类。内部包裹了一个协程对象，并**绑定了事件循环**。
- **核心特性**：创建 Task 的**那一刻**，包裹的协程就**立即被调度**到事件循环中去了（即使还没写 `await task`）。它代表着一个**正在后台并发运行**的工作。
- **状态管理**：拥有明确的状态机（`Pending` 进行中、`Done` 已完成、`Cancelled` 被取消）。可以随时查询 `task.done()`，或调用 `task.cancel()` 终止它。

---

## 3. 联动执行原理（事件循环如何运行它们）
> **重点**：事件循环（Event Loop）**不直接运行协程**，它只运行 Task。

| 操作 | 底层行为 | 执行模式 |
| :--- | :--- | :--- |
| `await coro` | Python 在后台**隐式地**将 `coro` 包装成一个临时的 `Task`，然后挂起当前任务去等待该临时 Task 结束。 | **串行**（子协程结束后，控制权返回给父协程）。 |
| `await task` | 该 Task 早已被注册在事件循环的队列里。`await` 只是让当前任务**挂起（让出CPU）**，去等待已在后台飞驰的 Task 拿回结果。 | **并发**（总耗时取决于最慢的那个 Task）。 |

---

## 4. 经典比喻（餐厅厨房模型）
> 把**事件循环**想象成**餐厅的厨房（调度中心）**。

- **协程（Coroutine） = 菜谱（Recipe）**  
  详细写了做菜的每一步，但只是一张纸，不会自己变成菜。

- **任务（Task） = 厨师手里的“工单” + 灶台**  
  当你把菜谱给厨师并说“开始做”（`create_task`），厨师就把菜谱贴在灶台上，开始切菜炒菜。这张“工单”代表该活**正在被实际执行**。你可以通过工单号（Task 对象）查询进度（`done`）或要求取消（`cancel`）。

- **`await` = “等菜”**  
  - `await coro`：厨师直接按你的菜谱炒菜，你只能站在灶台前等，不能干别的。  
  - `await task`：你提前把菜谱给了好几个厨师（先创建多个 Task），然后坐在座位上挨个喊“端上来”。虽然你是挨个喊的，但几道菜**同时**在后厨做，总时间取决于最慢的那道菜。

## 5. 全方位对比表格

| 维度 | 协程 (Coroutine) | 任务 (Task) |
| :--- | :--- | :--- |
| **是什么** | 可暂停的函数（生成器） | 包裹协程的调度单元（Future） |
| **创建时机** | 调用 `async def` 函数时 | 调用 `asyncio.create_task()` 时 |
| **是否立即执行** | ❌ 否，是个“冷”对象 | ✅ 是，创建即调度到事件循环 |
| **能否取消** | ❌ 不能（只有 Task 能调用 `cancel`） | ✅ 可以（`task.cancel()`） |
| **能否查询状态** | ❌ 不能（无法知道跑没跑完） | ✅ 可以（`task.done()`, `task.result()`） |
| **能否被 `await` 多次** | ❌ 不能（只能 `await` 一次，再次会报 `RuntimeError`） | ✅ 可以（后续 `await` 直接返回缓存结果） |

---

## 6. 一句话记忆法
> **协程是“待办事项清单”上的文字，任务是“正在执行该事项的线程/进程”。**  
> 事件循环只看得到任务，看不到协程；只有把协程交到任务手里，并发才真正发生。
