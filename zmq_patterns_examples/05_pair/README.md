# PAIR —— 一对一专线

## 心智模型

```
PAIR ◀──────────────▶ PAIR
    (完全对等，双向，无角色区分)
```

PAIR 是最简单也最"原始"的 pattern：**只能是一对一**，两端完全对等，没有"客户端/服务端"、"发布者/订阅者"这种角色区分，双方都可以随时 `send()`/`recv()`，不受任何顺序限制（不像 REQ/REP 那样有严格交替要求）。

## 关键特性

- **1 对 1**：一个 PAIR socket 只能连接（或被连接）一个对端，第二个连接会替换掉第一个，而不是像 ROUTER/PUB 那样同时管理多个连接。
- **无消息顺序限制**：随时发、随时收，双方地位完全对称。
- **官方文档建议**：主要用于**同一进程内的线程间通信**（配合 `inproc://`），很少用于跨网络/跨进程场景，因为它没有自动重连、没有负载均衡这些"网络友好"特性。

## 什么场景用 PAIR

- 同一进程内，主线程与某个工作线程之间需要双向、无格式限制的控制通道（比如"启动/停止"信号、状态汇报）。
- 两个进程之间确实只需要单纯的一对一双工通信，且不需要 ZMQ 其他 pattern 的负载均衡/多连接管理能力。

## 什么场景不该用

- 需要一对多、多对一 -> PAIR 完全不支持，换用 PUB/SUB、PUSH/PULL 或 DEALER/ROUTER。
- 需要跨网络、需要自动重连和负载均衡的健壮性 -> 优先考虑 REQ/REP 或 DEALER/ROUTER。
