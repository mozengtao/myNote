# 第 13b 课：五个代表例（进入 / 退出）

主例「播放器框上的套接字与渲染」在 `code/`。其余四例只建立「副作用钉在框上」的直觉。

---

## 例 1：播放器渲染与套接字（主例）

**问题**：走进 `PLAYING` 开渲染，离开就关；走进 `CONNECTING` 开套接字尝试，离开就关。`STOP` 还要退出 `ACTIVE`。

**状态图**：见 `LESSON.md`。

**状态表**：箭上只留「会话级」动作；渲染与套接字不进 Action 列。

**实现**：`code/c/player_hsm.c`、`code/cpp/player_hsm.cpp`、`code/python/player_hsm.py`。

**复杂度**：5 个框的进入 / 退出 + 一次 LCA 转移。

**工业用途**：播放器会话与绘制生命期。

**常见缺陷**：`DATA_STARVE` 也退出 `ACTIVE`；或 `STOP` 不退出父框。

**重构**：音量不要做成外部转移——留给 13c。

## 例 2：监听套接字的开与关

**问题**：服务端在 `LISTENING` 时必须占着端口；离开 `LISTENING`（到 `CLOSED` 或 `DRAINING`）必须 `close`。若只在「用户点停止」那支箭上关，超时路径会泄漏。

| 状态 | Entry | Exit |
|------|-------|------|
| LISTENING | bind + listen | close fd |
| DRAINING | print drain | — |

`TIMEOUT` 与 `STOP` 都应经过 `exit LISTENING`，而不是各写一份 `close`。

**复杂度**：1 个关键框。

**工业用途**：TCP 监听、Unix 域套接字。

**常见缺陷**：进入里 `listen`，退出里忘记 `close`，第二次进入 `EADDRINUSE`。

**重构**：失败的 `bind` 应变成事件，不要在进入里死循环。

## 例 3：文件句柄

**问题**：`READING` 进入时 `open`，退出时 `close`。读完、出错、取消三条箭都离开 `READING`。

```
IDLE --START--> READING --DONE--> IDLE
                   |--ERROR--> IDLE
                   |--CANCEL--> IDLE
```

三支箭的 Action 可以不同（交付数据 / 报错 / 安静），`close` 只属于退出。

**复杂度**：1 个框，3 支出箭。

**工业用途**：配置加载、固件读取。

**常见缺陷**：只在 `DONE` 上 `close`，取消路径泄漏。

**重构**：与本课 `PLAYING` 的渲染同构。

## 例 4：UI 页面挂载

**问题**：进入 `SETTINGS` 挂载控件，退出卸载。从设置去帮助、从设置按返回，都必须卸载。把「挂载」写在「打开设置」那一支箭上，从帮助返回设置时会漏挂载，或从不卸载。

| 状态 | Entry | Exit |
|------|-------|------|
| SETTINGS | mount widgets | unmount widgets |
| HELP | mount help | unmount help |

**复杂度**：2 个页面框。

**工业用途**：嵌入式菜单、桌面偏好窗口。

**常见缺陷**：退出里再投递「打开帮助」，重入把卸载顺序打乱。

**重构**：13c 的内部转移适合「页面内改一个滑条」，不适合换页。

## 例 5：教学 TCP 的 TIME_WAIT

**问题**：进入 `TIME_WAIT` 武装 2MSL 定时器，退出则取消。无论是定时器到期去 `CLOSED`，还是 RST 提前离开，定时器都应被退出清掉。

本例不实现 TCP。对照本课：定时器属于框，不属于「到期」那一支箭。

**复杂度（直觉）**：1 个框的进入 / 退出。

**工业用途**：连接残留、端口重用。

**常见缺陷**：只在到期箭上取消定时器，RST 路径留下悬空超时事件。

**重构**：第 06 课的超时数据 + 本课的退出清理。
