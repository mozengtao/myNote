# 第 13d 课：五个代表例（浅 / 深历史）

主例「停止后再播放：无历史 / H / H*」在 `code/`。

---

## 例 1：播放器 Seek 后停止（主例）

**问题**：离开 `ACTIVE` 时人在 `PLAYING.SEEKING`。再 `PLAY`：无历史回连接；浅历史回 `PLAYING.NORMAL`；深历史回 `SEEKING`。

**状态图**：见 `LESSON.md`。

**状态表**：`PLAY` 三行按 `mode` 分叉；`STOP` 写两个槽。

**实现**：`code/c/player_hsm.c`、`code/cpp/player_hsm.cpp`、`code/python/player_hsm.py`。

**复杂度**：2 个历史槽 + 1 个模式；`PLAYING` 多一层。

**工业用途**：播放器中断恢复。

**常见缺陷**：浅历史误读内层槽，三种模式只看见两种。

**重构**：进度秒数是数据，即使深历史回到 `NORMAL` 也可以从上下文seek。状态只记局面。

## 例 2：设置页离开再回来

**问题**：用户从「网络」子页跳到系统对话框，再回来。浅历史：回到「设置」默认子页「通用」。深历史：回到「网络」。

```
SETTINGS
  GENERAL     （默认）
  NETWORK
```

`H` 与 `H*` 的差别就是本课 `PLAYING.NORMAL` / `SEEKING`。

**复杂度**：1 个盒子 + 2 叶子。

**工业用途**：手机设置、车机菜单。

**常见缺陷**：用 `last_was_network` 布尔，和「是否在设置里」打成非法组合。

**重构**：对话框是另一台机（第 10 课）还是历史，取决于对话框是否拆掉设置盒子。本课假定拆掉。

---

## 例 3：协议「上次模式」

**问题**：无线电台有扫描 / 关联。暂停省电后醒来：浅历史回到「已关联」盒子的默认（在线），深历史回到暂停前的休眠叶子。

本例只对照第 12 课的直觉，不实现。第 12 课禁止把省电做成顶层；本课说明：省电若在 `CONNECTED` 盒子里，醒来用 `H` 还是 `H*` 是产品选择。

**复杂度（直觉）**：与主例同构。

**工业用途**：省电唤醒。

**常见缺陷**：无历史醒来却去重新扫描——有时正确（会话已死），有时浪费。

**重构**：会话是否还有效是监护，不是历史槽本身。

## 例 4：编辑器工具

**问题**：绘图工具有「选择 / 画笔」，画笔里还有「细 / 粗」。切到文字工具再切回绘图：

- 浅：回到画笔默认「细」
- 深：回到「粗」

与 `PLAYING.NORMAL` / `SEEKING` 同构，只是换了名字。

**复杂度**：2 层盒子。

**工业用途**：创意软件工具栏。

**常见缺陷**：一个全局 `last_tool` 字符串，图层一深就不够用。

**重构**：每层一个槽，正是本课的 `active_hist` / `playing_hist`。

## 例 5：缓冲上的浅深相同

**问题**：`BUFFERING` 没有孩子。从缓冲停止再播放，`H` 与 `H*` 都恢复 `BUFFERING`。差别只出现在「直接孩子还是复合」时。

主例 `main` 的三条对照用 `SEEKING` 就是为了让差别可见。本例提醒：不要用「从缓冲恢复」来证明你理解了深历史。

**复杂度**：0 个新状态。

**工业用途**：判断测试是否覆盖了 `H*`。

**常见缺陷**：测试只覆盖一层，就宣称实现了深历史。

**重构**：挑战练习里的 `PAUSED` 才是第二层测试点。
