# 第 06 课参考答案

先自己做 `lessons/06-elevator/quiz.md`，再对答案。

## 1. `TICK` vs `TIMEOUT_DOOR`；减到 0 直接改状态？

`TICK` 是节拍，可能什么也不做（`IDLE` 里）。`TIMEOUT_DOOR` 是曾经预约「最多再等 N 拍」之后、有业务含义的到期事件。减到 0 直接 `state = IDLE` 不算本课超时：关门没经过分发，表上没有到期这一行，复盘分不清是人按还是时间到。

## 2. `DOOR_CLOSE` 与 `TIMEOUT_DOOR` 能共用关门动作吗？

可以，动作都是关门回 `IDLE`。表上必须留下 **事件名不同**：复盘才能知道是人按还是到期。

## 3. 为何 `door_ticks`、`current_floor` 是数据不是状态？

它们是整数（还剩几拍、在哪一层），取值不是有限局面名。做成 `STATE_DOOR_TICK_2` 会按拍数复制框，状态爆炸。状态只有 `IDLE` / `MOVING` / `DOOR_OPEN`。

## 4. `IDLE` 里收到 `TICK`？若也减 `door_ticks`？

应忽略（无动作、状态不变）：没有门在倒数。若在 `IDLE` 也递减，会误触发过期的关门，或把已清零的计数再减穿。

## 5. 看门狗 `KICK` 对应哪次重新装载？共同三步？

对应开门时（或挡住时）**重新装载** `door_ticks = N`。共同三步：

1. **装载**：写入剩余拍数（`KICK` / `ARRIVE` 装门等候）
2. **递减**：每个 `TICK` 减一
3. **到期事件**：减到 0 变成 `TIMEOUT_DOOR`（看门狗则是复位事件）
