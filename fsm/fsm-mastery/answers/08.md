# 第 08 课参考答案

先自己做 `lessons/08-tcp/quiz.md`，再对答案。

## 1. `fsm_dispatch` 三步；`defined = 0` 时哪步不应发生？

三步：**查找** `table[state][event]` → 有格则执行 **动作** → **改状态** 为 `next`。`defined = 0` 时查找仍发生（读到缺格）；**动作和改状态都不应发生**（忽略）。

## 2. 为何 `TIMEOUT` 要写成表上两行，而不是全局重传函数？

同一事件在不同状态下含义相反：`SYN_SENT + TIMEOUT` 是重传 SYN、留在 `SYN_SENT`；`TIME_WAIT + TIMEOUT` 是收摊、回 `CLOSED`。写成一个全局重传函数，会在 `TIME_WAIT` 误重传。这和嵌套 `switch` 里把 `TIMEOUT` 动作拷错行、或 `default` 写错是同一类错误。

## 3. 教学路径省略了哪个 RFC 状态？哪一次 ACK 不再单独等待？

省略 **`SYN_RCVD`**。`LISTEN + RCV_SYN` 直接进 `ESTABLISHED` 后，三次握手里 **第三次 ACK**（对端对 SYN-ACK 的确认）不再被单独等待。

## 4. 五种形态；本课采用哪一种？State Pattern 为何不适合？

| 形态 | 本课 |
|------|------|
| 嵌套 `switch` | 第 03–07 课用过，本课不用 |
| **表驱动 `{action, next}`** | **采用** |
| 每格一个 handler 的函数指针表 | 不采用（格子过肥，handler 再改状态则 `next` 撒谎） |
| State Pattern | 不采用 |
| 生成式 FSM | 不采用 |

State Pattern 适合状态少、事件集合还在长的 GUI。协议控制面相反：状态集合相对稳定，事件是段标志组合；每状态一个类，加事件要改所有类。

## 5. 测试 `CLOSED + RCV_FIN` 必须忽略（无网卡）

喂事件脚本：当前 `CLOSED`，分发 `RCV_FIN`。断言：打印 `ignore`（或等价），状态仍是 `CLOSED`，无 `send` 动作。
