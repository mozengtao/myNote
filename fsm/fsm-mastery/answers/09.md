# 第 09 课参考答案

先自己做 `lessons/09-bgp/quiz.md`，再对答案。

## 1. `fsm_tick` 可以调 `fsm_dispatch` 吗？到期做什么？`fsm_run` 循环条件？

**不可以**直接调 `fsm_dispatch`。到期只 **入队** 对应的 `*_EXPIRED`。`fsm_run` 的循环条件是：**队列非空则取出再查表**（`while (dequeue) dispatch`）。

## 2. 为何 `ESTABLISHED` 不能共用一个 `TIMEOUT` 表示 Keepalive 和 Hold？

同一状态下两只钟含义相反，必须拆成两个事件、两行表：

| Current State | Event | Next State |
|---------------|-------|------------|
| ESTABLISHED | KEEPALIVE_EXPIRED | **仍是 ESTABLISHED**（`send KEEPALIVE`，再武装 Keepalive） |
| ESTABLISHED | HOLD_EXPIRED | **IDLE**（拆会话） |

合成一个 `TIMEOUT`，心跳到期会把自己拆掉。

## 3. 把 `TICK` 从协议事件里拿掉，哪两个模块边界变清晰？

**定时器子系统**（`fsm_tick`：只递减，到期只入队）和 **协议表**（`fsm_dispatch`：只查表，保持纯）。第 06 课是在 `dispatch(TICK)` 内部改写；本课时钟不再是协议事件。

## 4. RFC 有 `Active`，本课没有。谁吸收了「TCP 还没好、还要再试」？实现必须等于 RFC 图？

用 **`CONNECT`** 吸收（ConnectRetry 到期仍停在 `CONNECT` 再试）。「实现必须等于 RFC 图」是错的：实现既会 **省略**（本课无 Active），也会 **增加** RFC 基础图没有的行为（例如 Graceful Restart）。

## 5. 如何证明定时器走了队列而不是 tick 改了状态？

测试脚本应看到：**tick 先打印钟的剩余值（不打印 `--HOLD_EXPIRED-->`）**，然后 **`run` 之后**才出现到期转移那一行。顺序是 tick 入队 → run 出队查表。
