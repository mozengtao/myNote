# 第 07 课参考答案

先自己做 `lessons/07-player/quiz.md`，再对答案。

## 1. 无限立刻再连 vs 本课重试；为何打印 `retries left`？

差在两样数据：`retries_left`（还能试几次）和 `wait_ticks` / `backoff_ticks`（下一次要等几拍）。不打印剩余次数，轨迹无法证明重试发生过，也无法批改。

## 2. 退避 1、2、4 解决什么？每次失败 `sleep`？

解决对端/信道拥塞时固定猛打会加重拥塞。每次失败 `sleep` 会回到第 06 课的错误：**在分发里阻塞**，后续事件进不来。

## 3. 第三次（预算内最后一次）`TIMEOUT` 为何改写成 `GIVE_UP`？

放弃必须是表上的一条转移（事件 `GIVE_UP` → `STOPPED`），不能在计数里偷改 `state`。这和第 06 课「到期变成事件」同一手法。直接 `state = STOPPED` 会让放弃路径无法画进表、也无法挂停止动作。

## 4. `DATA_STARVE` 进 `BUFFERING` 为何不减 `retries_left`？

缓冲是已连上后缺码流，不是连接失败。共用计数器的话，播着播着卡顿几次就会误 `GIVE_UP`，用户看见「明明在播却突然停止」。

## 5. 为何不必第五个状态 `WAITING_RETRY`？

退避期间局面仍是「还没连上、还在连」。用 `wait_ticks > 0` 当监护即可区分「正在试」和「正在等下一枪」。多一个状态不增加信息，只增加表行。
