# 第 04 课参考答案

先自己做 `lessons/04-101-detector/quiz.md`，再对答案。

## 1. 什么是守卫？和事件有何不同？

守卫是箭头上必须为真的布尔条件；为假则这条箭头不点火。事件命名「来了一种输入」；守卫批准「这一位是否等于本行要求的值」。前缀进度留在状态里，位是否匹配写在箭头上，不必再造 `S0_expect1` 这种框。

## 2. 没有守卫、把位写进状态名

四个前缀各乘两种位，大约 **8** 个框。问题：前缀（匹配到哪）和输入（这一位是什么）缠在一起，框不再表示进度。

## 3. 已在 `S101` 再来 `BIT1`

下一状态是 `S1`，不是留在 `S101`。`S101` 的末位已是 `1`，再来一个 `1`，当前后缀是 `11` 里末尾那个 `1`，可当作下一段 `101` 的前缀。若留在 `S101`，等于声称后缀仍是 `101`，但 `1011` 的末三比特是 `011`。

## 4. PIN 锁：同一 `UNLOCK`，两个去向

- 事件：都叫 `UNLOCK`
- 守卫：`PIN 匹配` → `UNLOCKED`；`PIN 不匹配` → 留在 `LOCKED`

## 5. 序列 `10101` 命中几次？逐步状态

命中 **2** 次。

| 比特后 | 状态 | 说明 |
|--------|------|------|
| （上电） | `S0` | |
| `1` | `S1` | |
| `0` | `S10` | |
| `1` | `S101` | 第一次 `101` |
| `0` | `S10` | 重叠，后缀 `10` |
| `1` | `S101` | 第二次 `101` |
