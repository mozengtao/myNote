# 第 14b 课参考答案

先自己做 `lessons/14-actor-fsm/14b-framework-compare/quiz.md`，再对答案。

## 1. 四个箭头的概念序列；哪一步对应 14a 的 `actor_send`？

```
消息进入 --> 邮箱 --> 分发 --> FSM 转移（改这一台的 state）
```

`tell` / `send` / `actor.send` / `so_5::send` 都对应 **只入队、不 `dispatch`** 的那一步，即 14a 的 `actor_send`。

## 2. 为何 XState 不是 Akka 的 JVM Actor 系统？两条教学 TCP 为何必须 `spawn`？

实质差别（至少两点）：

- **一等公民**：XState 是状态图（数据）；Akka 是隔离对象 + 邮箱。
- **分布式 / 监督**：XState 不以跨机器重启、监督树为目标；Akka 有父 Actor 监督与分布式路径。
- **邮箱**：XState 默认是解释器事件队列；没有 `spawn` 的正交区域 **共享同一解释器**。

两条教学 TCP 是两个会话实例，各需一份邮箱。同一张图里两个正交区域会共享广播事件，失败会串，不能代替两个 `spawn` / 两次 `interpret`。

## 3. 四行对照：各解决哪一种膨胀？

| 模型 | 解决哪一种膨胀 |
|------|----------------|
| 扁平 FSM | 「现在是什么」没有名字（布尔/标志打架） |
| HSM | 状态按深度重复，进入/退出抄很多遍 |
| Statechart | 一台机里还要正交、历史、图上广播 |
| Actor | **对象个数 × 共享内存**：N 条连接互相写 `state` |

N 条连接互相写 `state` → **Actor**。`ESTABLISHED` 内部还要省电 → **HSM**（或 Statechart 子状态），不是第三个角色。

## 4. 何时选 CAF（或 SObjectizer）而不是 14a 的五十行？

14a **不够**、框架才提供：类型化消息、低开销多 Actor 调度、监督组 / cooperation、生产级邮箱边界（任举其一）。框架 **不必上**、五十行就够：教学两条本地连接、把「只许 `send`、不许写对方 `state`」写进纪律。

已在 C++、要类型化消息与低延迟调度时选 CAF；要 mbox / cooperation 时选 SObjectizer。

## 5. Akka 监督树重启 vs 14a 入队 `RESTART`：对「B 继续跑」和「A 的 `state` 还在不在」？和第 12 课？

- **B 继续跑**：相同。只处理出错的那一个，不碰邻居。
- **A 的 `state` 字段**：可能不同。14a 仍是同一对象，走 `ERROR → CLOSED`。Akka 重启子 Actor 可能 **销毁再创建**，旧的 `state` 字段不再是原来那块内存。
- **和第 12 课**：第 12 课是 **同一台机** 回到熟知状态（`SCANNING`）。监督是 **角色级** 重建对象。可以共存（新实例再从 `CLOSED` 走会话恢复），但不能当成同一个机制：一个改局面，一个换对象。
