# 第 13b 课参考答案

先自己做 `lessons/13-hsm/13b-entry-exit/quiz.md`，再对答案。

## 1. `PLAYING` 收到 `STOP` 的进入 / 退出 / 转移动作顺序

1. `exit PLAYING`（停渲染）
2. `exit ACTIVE`（活动级资源）
3. 转移动作 `stop session`
4. `entry STOPPED`

必须出现 `exit ACTIVE`：`STOP` 离开盒子，LCA 在盒子之外；只退叶子会把活动级资源漏掉。

## 2. `PLAYING` 收到 `DATA_STARVE` 为何不能 `exit ACTIVE`？

LCA 是 `ACTIVE`，人还在盒子里，只换叶子：`exit PLAYING` → 转移动作 → `entry BUFFERING`。若错误退出父框，缓冲被当成断连，和第 07 课「缓冲不是断连」冲突。

## 3. 「开始渲染」为何写在 `PLAYING` 的进入里？

只要走进 `PLAYING` 就必须渲染，不论来自 `CONNECTED` 还是 `DATA_OK`。写在两支箭上会漏抄，状态已是 `PLAYING` 画面却是黑的。

## 4. 进入父→子，退出子→父；反了会怎样？

- **套接字**：若先 `entry CONNECTING`（开套接字）再 `exit STOPPED`，顺序虽常能凑合；更糟的是离开时先退父再退子——活动资源先放掉，子套接字还开着。进入若先子后父：子已开套接字，父还没进入，活动会话不存在。
- **活动会话**：`STOP` 若先 `exit ACTIVE` 再 `exit PLAYING`，活动已结束，渲染器却还在跑。

正确：退出先叶子后父；进入先父后叶子。

## 5. 第 05 课转移动作 vs 本课进入 / 退出如何分工？

转移动作挂在 **这一支箭** 上（「走的时候做一次」）。进入 / 退出挂在 **框** 上（「只要待在这里就必须为真」）。不该再按箭复制的：开/关渲染、开/关套接字尝试——凡是「进出这个局面」都要做的副作用。
