# 第 13f 课参考答案

先自己做 `lessons/13-hsm/13f-pseudostates/quiz.md`，再对答案。

## 1. 为何 Choice / Fork / Join / Junction 不应出现在 `Fsm.outer` 或叶子枚举里？

它们不是可停留局面：处理当前这个事件的过程中就被走完。当前状态在有伪状态的图上仍指 **叶子**（外加正交时的两列）。写成 `CHOOSING` 等，日志会骗人。

## 2. Choice 和第 04 课画在单支箭上的监护差在哪？为何不拆 `PLAY_CACHED` / `PLAY_UNCACHED`？

监护可以挂在任意一支箭上。Choice 是 **同一源、同一事件、多条出路挤在一个决策点**，监护在 **到达菱形的那一刻** 求值。用户只按了一次 `PLAY`；拆成两个事件等于把一次按键说成两种用户动作。

## 3. Junction 和 Join 差在「等不等」？`STOP` 做成 Join 会卡在哪？

Junction **不等**，只是箭的接头。Join **等** 各区域到达指定状态。把 `STOP` 做成 Join，用户按停止会卡在 **等两列都「就绪」**（未进 `ACTIVE`、还在 `CONNECTING` 时甚至永远等不到第二列）。停止应立即到 `STOPPED`。

## 4. 未缓存路径上，为何 `STARTED` 必须出现在 `WIFI_RECOVER` 之后、而不是 `CONNECTED` 当时？

`CONNECTED` 时 Fork 把 `net` 故意放到 `WIFI_WEAK`，Join 条件不成立。等 `WIFI_RECOVER` 后两列才都就绪。这证明：**Fork 只是同时点亮两列，不保证立刻 Join；Join 必须等待。**

## 5. 为何不能用线程实现 Fork？第 14 课解决哪件本课不做的事？

Fork 是同一次 `dispatch` 里给两列赋值，中间不能穿插别的事件。线程是另一套并发，不是图上的杠。第 14 课解决 **许多对象同时活着、消息不能直接改对方字段**（并发隔离 / Actor + 邮箱）。不要在本课开线程模拟 Fork。
